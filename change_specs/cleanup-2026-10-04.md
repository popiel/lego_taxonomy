# Codebase Cleanup Specification

Status: implemented (sbt 208 tests / 20 suites green; npm 45 tests / 2
suites green). Blue-mode refactoring: user-visible behavior preserved.
Covers the 2026-10-04 codebase audit: dead code, redundancies, and style
inconsistencies. TDD where behavior is touched; existing suites are the
characterization net.

Implementation notes beyond the plan:

- `ScalaTestWithActorTestKit` provides Matchers and BeforeAndAfterAll
  but not AnyWordSpecLike, so kit-based specs keep `with
  AnyWordSpecLike` and only drop the genuinely redundant mixins.
- The findBasePart tests moved to TaxonomyDataSpec verbatim.
- The verb normalized to `should` everywhere.
- The blocking-dispatcher lookup lives in `Routes.all`
  (`DispatcherSelector.fromConfig`), passed into
  `processUploadedFile` as an explicit parameter.
- Bind-failure logging covers both HTTP and HTTPS bindings.

## Goals

1. Remove production code with no references (dead methods, dead messages,
   dead imports, redundant config wiring).
2. Fix hygiene defects found by the audit (resource leak, println logging,
   deprecated imports, CSS gaps).
3. Normalize test conventions (spec base classes, verbs, shared stubs,
   deterministic synchronization) and retire misplaced tests.
4. Finish the convention that runtime budgets live in `application.conf`
   via `Timeouts`, and make suppressed failures observable.

## Requirements

- R1: no user-visible behavior changes in G1/G2 beyond log output; the
  full sbt and Jest suites plus the exact-markup golden spec stay green.
- R2: G1 removals must be verified reference-free before deletion.
- R3: G3 changes test code only; production code is untouched except the
  `GetTaxonomy` decision (keep).
- R4: G4 is behavior-adjacent (timeouts move to config with identical
  values; upload parsing moves to a blocking dispatcher; bind failures
  become logged) and must pass the golden suite plus a manual smoke run.

## Characterization tests (written before implementation)

- The existing 203-test sbt suite, 45-test Jest suite, and
  `RenderingGoldenSpec` (exact rendered markup per lookup via, image
  bounds, URL/prefill behavior) pin all preserved behavior. G1/G2 ride
  on them unchanged.
- No new characterization is needed: every G1 item is verified
  reference-free (audit greps recorded below), so deletion cannot change
  behavior; G4 keeps all timeout values identical, only relocated.

## Design

### G1 — Dead-code removal (zero behavior change)

1. `hasImageInZip`: delete from `LDrawImageFetcherTrait`
   (`LDrawImageFetcher.scala:17`), the class implementation (`:122-132`),
   and `ImageResolverSpec`'s `StubLdraw` (`:42`). No callers remain
   since the PartsProcessor rewrite.
2. `Data` dead members: delete `setNumToSet`, `setNumToInventory`,
   `inventoryIdToParts`, `elementByPartNumAndColorId`
   (`Rebrickable.scala:68-70,75-76`). Keep `elementIdToElement` (used by
   `elementIdToDesignId`), `partNumColorIdToElement`, `partNumToPart`,
   `colorIdToColor`.
3. `RebrickableBinaryCache`: delete `delete` (`:55`), `deleteLDraw`
   (`:140`), `getLDrawAgeHours` (`:125`).
4. `RebrickableSchedulerActor`: delete the never-sent
   `LDrawPrefetchComplete` (`:19`) and its handler branch (`:76-78`) —
   the prefetch at `:66` is synchronous.
5. Unused imports: `HttpServer.scala:23` keeps only `RebrickableHolder`
   (`Color, Data, Element, InventoryPart, Part` unreferenced);
   `TaxonomySortMain.scala` drops `Behavior`, `Behaviors`,
   `ExecutionContext`.
6. runWebMode config fossil: drop
   `ConfigFactory.parseString("akka.http.parsing.cookie-parsing-mode = raw").withFallback(ConfigFactory.load())`
   (`TaxonomySortMain.scala:26-28`) — `application.conf:1` already sets
   it (plus the web budgets); use the default config and drop the
   now-unused `ConfigFactory` import.

### G2 — Hygiene fixes

1. `DiskCache.scala:78` — close the `Source` in `loadCache` (try/finally,
   same pattern as the earlier `CsvReader` fix).
2. `DiskCache` printlns (`:84,:104`) → `context.log.warn`, logged at the
   call sites where the actor context is in scope.
3. `TaxonomyParser.scala:91` println → `LoggerFactory.getLogger` object
   logger (the `BricksetPartFetcher` convention), debug level (it fires
   per main category during parse).
4. `scala.collection.JavaConverters._` → `scala.jdk.CollectionConverters._`
   in `BricksetPartFetcher.scala:12` and `TaxonomyParser.scala:6`.
5. CSS: add a modest `.uploaded-file-name` style (gray secondary text);
   replace the stray tab at `parts-sorter.css:25-26` with spaces.

### G3 — Test hygiene (tests only, plus the GetTaxonomy decision)

1. Move the `findBasePart` describe-block (4 tests) from
   `BricksetPartFetcherSpec` to `TaxonomyDataSpec` — its proper home.
2. Shared test support: new
   `src/test/scala/com/wolfskeep/TestStubs.scala` with the behavior
   factories duplicated across specs: stub rebrickable from `Data`,
   fake processor from `legoPartFor`, fake image resolver, and a
   `spawnActor` helper. `HttpServerSpec` and `RenderingGoldenSpec`
   collapse accordingly; `TaxonomyHolderSpec`'s stubs adopt it.
   `ImageResolverSpec`'s resolver-specific stubs (`StubLdraw`,
   `CacheStub`, `DownloaderStub`) stay local — they are cohesive to
   that spec.
3. Spec normalization: all `ScalaTestWithActorTestKit` specs carry
   `with Matchers`; `RebrickableSpec` becomes
   `AnyFlatSpec with Matchers` with `assert` → `shouldBe`; verbs unify
   on `should` (the two route specs' `must` renamed).
4. Deterministic sync: replace `Thread.sleep(100)` in
   `PartsProcessorSpec:40` and `RenderingGoldenSpec:103` with a
   probe-based await — ask `GetTaxonomy` and await the reply (the
   reply proves `SetTaxonomy` landed); fix `DownloadQueueSpec:184`'s
   `sleep(50)` with a probe expectation at the actual race point.
5. `TaxonomyHolder.GetTaxonomy` / `TaxonomyDataResponse`: KEEP — a
   legitimate holder read-API used by two specs, and it becomes the
   deterministic-sync tool in (4). (Removal would also be defensible;
   revisit only if it stays single-purpose.)

### G4 — Convention/hardening (prefix-match simplification dropped)

The O(n²) `uploadLocalPrefixMatch` stays as-is: n is small (hundreds to
low thousands) and the clearer code is worth more than the optimization.

1. Timeout literals → config: new `Timeouts.Service` case class reading
   `application.conf`:
   ```
   lego-taxonomy.service {
     lookup-ask = 5s        # PartsProcessor -> TaxonomyHolder.LookupParts
     rebrickable-ask = 1s   # TaxonomyHolder -> RebrickableHolder.GetData
     brickset-ask = 90s     # ImageResolver -> CachedDownloader (FetchPartDetails)
     image-ask = 3s         # Routes -> ImageResolver (poll sanity bound)
   }
   lego-taxonomy.scheduled {
     rebrickable-fetch = 30m  # RebrickableSchedulerActor -> FetchAll
     batch-probe = 2m         # batch-mode GetTaxonomy await
   }
   ```
   with positivity `require`s, threaded as default parameters:
   `PartsProcessor`, `TaxonomyHolder`, `ImageResolver`, `Routes.all`,
   `RebrickableSchedulerActor`, and the batch probe. Values identical to
   today's literals. Constructor default parameters (Downloader
   `requestDeadline`/`retryInterval`, DownloadQueue `pauseDuration`,
   TaxonomyScheduler `cycleTimeout`) stay as-is — a consistent existing
   pattern.
2. HTTPS binding observability (`HttpServer.start`): log both binds'
   failures via `actorSystem.log` instead of discarding the HTTPS future;
   still return the HTTP binding. Drop `runWebMode`'s unused
   `bindingFuture` val.
3. Upload parsing off the route dispatcher: `processUploadedFile`'s
   body moves to `akka.actor.default-blocking-io-dispatcher` via
   `DispatcherSelector.fromConfig` on `Routes.all`'s system (same
   discipline as `ImageResolver`).

## Test plan (TDD ordering)

- G1/G2: no red-first needed — pure deletions/hygiene; the existing
  suites must stay green after each group. Compile after each file
  edit.
- G3: move/normalize tests; suite counts shift only by relocation
  (findBasePart block) and assertions converted in `RebrickableSpec`.
  The deterministic-sync replacements must not become flaky: a missed
  probe expectation fails loudly rather than sleeping longer.
- G4: red-first for the `Timeouts.Service` invariants (a new
  `TimeoutsSpec` block mirroring the `Web` guards: all service/scheduled
  budgets positive). Behavior tests are the existing route/golden specs
  — values unchanged. HTTPS bind logging and the blocking-dispatcher
  move are verified by compilation + suites + smoke.
- Final: `sbt test` and `npm test` green, then the manual smoke below.

## Out of scope

- `PartsProcessor.uploadLocalPrefixMatch` O(n²) — deliberately kept.
- `akka.http.server.request-timeout` in conf plus `withRequestTimeout`
  duplication — intentional belt-and-braces.
- `TaxonomyFetcher`'s test-seam `apply(downloader, cache)` — deliberate.
- `Data`'s lazy maps recomputing per `data.copy` — documented design.
- `ImageResolverSpec` mirroring the resolver's private cache-key strings.
